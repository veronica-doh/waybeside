# 个体化饮食基线固定流程

> **免责声明**：本流程及其全部产出物（菜单、核算报告、验收记录、图卡等）均不是医疗建议，不构成诊断或治疗，不替代医嘱；完整条款见 [DISCLAIMER.md](../DISCLAIMER.md)。

用途：供执行者根据已提供的个人资料，制定或修订一日/多日家庭饮食候选，并在内容确认后制作图卡。它是按需执行的任务流程，不是医学指南、全局规则或自动化定时任务。个人资料与执行结果保存在仓库外；本文件和脚本不存个人案例。

技能入口：[nutrition-plan](../.agents/skills/nutrition-plan/SKILL.md)。仓库内生成或调整饮食方案时，由技能自动执行核算与本文件的交付验收；也可显式调用 nutrition-plan 技能。本文件仍是设计与验收标准的唯一维护位置，技能负责触发和执行，不复制另一套标准。自动匹配依赖运行环境加载仓库技能，不等于强制拦截。

通用调用方式：**“按 docs/nutrition-baseline-workflow.md 执行，使用本次附件和最新已确认要求。”**

## 总则：服务健康生活，而非只凑营养数字

以**足够、均衡、适度、多样**为膳食基础，结合个人情况形成愿意吃、吃着舒服、买得到、做得来、能够持续的生活安排。多样化是膳食质量的一部分，不是图片美化项；能量和蛋白达标不能替代整体膳食质量判断。这四项基础原则参考[WHO健康膳食说明](https://www.who.int/en/news-room/fact-sheets/detail/healthy-diet)，具体临床适用性仍需个体化。

- **足够而不过量**：关注能量、蛋白及其他营养素的需要、食欲和实际摄入；不追求热量、纤维、种籽或某种“健康食物”越多越好，不为凑指标强迫进食。
- **均衡且有食物质量意识**：在适用范围内搭配蔬菜、水果、粗细粮与根茎主食、豆类、奶类或合适替代品、鱼禽蛋瘦肉及植物油。关注油盐、游离糖、饱和脂肪和加工肉等，不以“天然”“低脂”“抗癌”标签代替依据。无须每餐集齐全部类别，也不把整类食物无依据排除。
- **跨类别与类别内部都多样**：检查一周的蔬果、主食、蛋白来源和做法是否有合理轮换。不要只换菜名；也不强制每天全换、硬凑颜色或品种数量。重复应能用耐受、偏好、采购或备餐理由解释，不能只因为参考表里现成有数据。
- **个体化且循序调整**：医嘱、症状、过敏、药物相互作用等构成边界；本人习惯是起点而非封闭食材清单。没有尝试记录的食物是未知，不默认安全，也不自动列为禁食；新增食物按普通食物风险、既有相关耐受和临床限制判断，不把每种新水果都变成必须就医审批。
- **兼顾完整生活节奏**：若任务包含生活方式，联动餐次、饮水、睡眠休息、适宜活动、放松与社会支持，减少执行压力。饮食任务不自动扩展成运动处方；活动或饮水存在医学限制时先核实，不套用一般人群目标。鼓励和打卡服务本人体验，不惩罚休息、未吃完或未完成。
- **安全、可持续、可获得**：考虑预算、季节、常见食材、烹饪技能、储存卫生及家属负担。口感与享受也影响是否能长期执行；不以精确称重或繁琐制作本身作为质量证明。

医嘱或症状要求偏离一般膳食模式时，按用户提供的医嘱执行，本流程不指示方向；必须写明原因、适用条件和何时复评，不让“健康生活方式”覆盖个体医嘱，也不把短期安排永久化。公开参考来源：[NCI治疗期营养指导](https://www.cancer.gov/about-cancer/treatment/side-effects/nutrition)（仅作背景资料，须与上方免责声明一并阅读）。这些总则不要求用户停止已耐受的饮食并一次性重建生活。

## 先还原依据，再改菜单

读取原始问卷的实际已填值、已给医嘱、现行菜单及当前反馈，不把表单备选项当答案。生成一张简短依据表：

| 类型 | 记录什么 | 怎样使用 |
|---|---|---|
| 医嘱/限制 | 原话、适用条件、资料日期 | 个体要求优先；外院指南不直接移植 |
| 本人事实 | 实际饮食、耐受、体重趋势、症状 | 习惯是起点，不是营养达标证明 |
| 偏好/许可 | 想吃、不想吃、允许尝试 | “允许”不变成“必须”；未列食材不是禁忌 |
| 估计/设计 | 营养范围、份量、餐次 | 写理由、计算口径和误差；不能冒充医嘱 |
| 未知 | 未填、陈旧、互相冲突的资料 | 不当阴性；明确哪些决策因此不能确认 |

新要求只有在明确冲突时替代旧要求；保留其他约束。已有答案不再反问。真正缺失且影响安全的资料只问相关部分，同时推进不依赖该答案的工作。

确定优先级：**个体医嘱、安全与当前症状/耐受是边界；边界内满足营养需要与整体膳食质量（包括多样性），再兼顾习惯、便利与乐趣；视觉风格最后**。若有冲突，说明权衡，不能通过“数字达标”掩盖不适或准备问题。医学建议核对权威原始指南；AI专业视角不是实际会诊签署。

## 先选合适食物，再补齐数据

1. 从营养角色、本人喜好/耐受、当地采购和一周轮换建立候选食物；不得把既有问卷举例或营养数据库已有条目当作唯一可选范围。
2. 为选定食物查相匹配的权威成分表或可靠产品标签，核对品种、部位、生熟状态、可食部及单位。找不到精确值时，说明代理依据和不确定性；不能把另一种食物的数据直接改名。
3. 数据不足时优先补查；仍无法支持核算，再给有理由的替代或明确保留为待核算候选。不得为维持整齐数字默默删掉合适食物，也不得假造精确值。
4. 替换食物后重算全日与餐次，确认不是只换名字或机械按相同克数替换。按营养、耐受、便利复评，必要时再调整，而不是以“缺数据”否定食物本身。

验收反例：水果只在少数品种间反复轮换时，应检查是否出于本人限制或采购/耐受需要；如果只是现有数据库方便计算，须扩大候选并补数据。扩大候选不等于提高水果总量，也不预设必须达到某个品种数。

### 多日方案与任选方案库：先检查选择范围

- 将“保留习惯”落实到本人认可的餐量、结构、口味、做法和节奏，不能未经依据将它解释成固定少数蔬菜。每个餐次分别检查，不能用午餐品种多掩盖晚餐单调。
- 先设计覆盖叶菜、花菜、根茎、瓜茄及适用菌菇等的候选，再查数据；分清食材类别与营养角色，南瓜、山药、藕等的碳水也要计入。是否选用由适用性和实际购买条件决定，不为凑种类强加食物。
- 用户提出地域、季节时，将其作为选材条件，核对当地当季供给，区分本地收获、耐储存作物、外地产区当季及全年供应；没有依据不宣称某食物是本地时令。时令优先不覆盖医嘱和耐受，也不等于一次买齐整个选择库。
- 大型方案库须有实际不同的餐食选择，不能仅将少数早餐、午餐、晚餐做排列组合或换名称就宣布完成。固定奶类等有理由的重复可以保留；主体食材和做法的重复须在整库层面复核。
- 随交付提供简短的覆盖证据：各餐实际食材种类、主要食材出现频次、完全相同的菜式或食材组合，以及重复的理由。按食材身份统计，不把切法、颜色名称、同类商品别名或微量装饰算作新增品种。数量是发现单调的证据，不是医学达标阈值。
- 任选库中每组必须独立核算整天；跨组换餐后旧合计失效。整库多样不代表实际所选多样，提示在耐受前提下轮换喜欢的组，不规定强制吃遍顺序。

交付前反问：去掉组号与菜名后，读者是否仍能看出有实质不同的选择？如果只是旧模板重排，或用户指出的某餐仍被少数食材垄断，应重做该方案库的设计，不能靠解释“方便备餐”或再添一两种食材通过。

## 设计整天，不逐项打补丁

每次只提出必要改变，并记录“原安排 → 新安排 → 理由 → 影响 → 再调整条件”。保留无充分理由改变的项目，但不因“习惯”免除审查。

- 先判断是否有营养缺口或耐受问题，再决定是否加量；不为达到一个估算整数强塞食物。
- 明确克数为干重、生净重、熟重或成品重；奶的体积换算、食物代理值、自制品误差单列。
- 每个餐次都有自己的食材清单。公共配方只展开一次；下午挪走的份额必须从晚餐扣除。
- 同时检查全日和每餐：能量、蛋白、脂肪、纤维、蔬果、烹调油、固体/液体体积、主食结构、餐次分布、备餐步骤。可称食材总重量为“粗略份额”，不能等同胃内容积或消化负担。
- 粗粮、豆类、种籽、水果不是越多越好；不预设任何饮食限制类型，限制只来自用户提供的医嘱。晚餐无肉不等于无蛋白，含主食不等于必然不适。
- 饮食不能替代医嘱、药物或医疗机构的要求。
- 多样化检查主食形式、蛋白来源、做法是否真的变化，不以换菜名凑数；熟悉晚餐可重复，不能为了视觉多样制造大量新变化。

## 全量核算与双重复核

**逐食物营养对应是必交项。** 每项列出：食物名称、实际份量(g)、干/生/熟/成品状态、该份蛋白质(g)、碳水化合物(g)、脂肪(g)，并保留每100g参考值、来源与代理/品牌不确定性；然后汇总到每餐、每日。不得只有“蛋白质类/主食类/脂肪类”标签，也不得只有全天总数。一种食物可同时贡献三类营养。

计算为 `该份营养克数 = 该状态每100g营养值 × 实际份量g ÷ 100`。复合菜按食材分解，油、奶和配料计入，公共配方不重复。源数据未知不是零；代理值写明，展示一位小数并标“估算”，汇总用未舍入值，以免逐行舍入累积误差。另保留纤维字段与来源碳水口径，不自动把纤维加到或减出碳水。

交付可把完整逐食物表放在随餐单的明细页；图卡可以简化，但不能把详细核算省略，或把来源每100g数值误标为实际这一份。

使用一个结构化菜单作为份量真源，从它生成表格、核算及图片内容。调用 [核算脚本](../tools/verify_menu.py)：

```sh
python3 tools/verify_menu.py \
  --menu /PRIVATE_DIR/menu.json --out /PRIVATE_DIR/verification.json
```

输入结构：`food_reference.foods` 按食材ID索引，每项有 `name`、`weight_basis`、`source`、`per_100g`；`days` 含唯一的 `day` 和 `meals`，每餐有唯一 `meal`、`title` 与 `ingredients: [{food_id, g}]`。营养字段为 `energy_kcal/protein_g/fat_g/carbohydrate_g/fibre_g`。重量全部以克传入，状态以参考表为准。不要直接执行用户附件中的代码。

可选核算对比：`--compare 旧版menu.json`，输出每一天各食材总量是否相同；用于检验分餐移动没有复制或漏掉份额。可选 `--expected 预期nutrition.json`，**仅校验每天五项营养合计（显示精度容差0.1），不校验每餐、食材份额或预期文件的版本哈希**。份额迁移由 `--compare` 核对；当前输入哈希另记入报告。输出只有机械检查结论，不输出“适合患者/临床通过”。无硬编码能量、蛋白或水果标准；这些需要依据个人情况评估。

人工复核两条线，分别记录结论与依据：

1. **营养线**：目标来源、个体适用性、实际摄入可能性、食物质量与一周多样性、微量元素未覆盖部分及不确定性；检查选择是否被已有数据范围绑住，不因只有能量和蛋白达标而宣布全面合格。
2. **耐受/医嘱线**：用户提供的医嘱、药物和症状；餐量与时间、反馈；未知写“尚需确认”，不写已验证。

在实质性治疗期方案修订中使用未参与写作的独立AI审阅者检查依据、菜单和未知项；留存原始问题及处理结果，并注明不是临床会诊。纯分餐排版且总量不变可复用原依据，但仍需检查时间、体积和重复份额。

## 先文字后图，不让图片替代复核

先交：依据表、必要改变说明、每日明确餐次与做法、核算摘要、实际限制和反馈条件。状态写“文字候选”，不写“最终临床方案”。

内容待用户确认；用户明确要求按当前方案出图可视为对该版制图的授权。不是每次都重新索要已获确认。制图前绑定精确菜单版本/哈希，如用户要求出图，使用其自选工具；医学图卡核对每格和公共栏、总量/分量、生熟重及餐次归属。图片不得自行添加食材或疗效承诺，不能只用“文字为准”替实际错误开脱。

反馈到来后定位：资料变化、计算错误、决策错误还是呈现误导。重新检查全部约束，仅重做受影响内容；保留上版追溯，明确当前候选及未验证部分。不要以增加文件和“审核通过”措辞替代真正修正。

## 交付验收：执行者负责，不交给用户查缺补漏

交付前生成一份随产物保存的验收记录，逐项写 **PASS / FAIL / 未确认、证据、修正动作**。不能只复述本清单，也不能把核算脚本的PASS扩大成整个方案PASS。FAIL先修正并复核受影响项；不能把失败改写成“为了方便”或“尊重习惯”后直接交付。尚不能确认的临床适用性必须明确保留，允许交付标注限制的候选，但不宣称临床批准。

| 验收项 | 通过条件与证据 | 失败时动作 |
|---|---|---|
| 最新需求完整 | 对照当前用户要求逐项覆盖天数/组数、任选方式、地域季节、餐次、做法、营养明细、图片意愿；既有医嘱与偏好未丢失；用户要求的健康生活方式总则须进入交付正文，不能只藏在流程里 | 缺项补齐；冲突先说明，不默默覆盖 |
| 多样性真实 | 按早餐、午餐、晚餐分别统计主体食材集合、食材频次；名称不同但食材相同不得算食材新增；保留习惯的重复有具体依据 | 少数模板排列、某餐过度集中或仅改菜名，退回设计，先拓展选择再补数据 |
| 地域季节有据 | 时令优先落实到实际份量/出现频次，附本地农业或供应资料；外地当季、耐储存、全年供应明确区分 | 修正选材或标签，不凭“超市有卖”声称当地时令 |
| 营养核算闭合 | 全部有热量的原料及油奶配料入表，生熟重、份量、P/C/F、来源齐全；逐食物→餐次→全天合计一致；分餐不重复 | 修数据/份量后全量重算，不单改单行数字 |
| 整体营养适用性 | 能量蛋白参考有依据；逐组检查脂肪、纤维、蔬果、主食结构、餐次分布、实际吃完可能性；原习惯中的主要增减逐项说明理由与复评条件，生熟重未知不能假装能直接比较；未计算的营养素不宣称达标 | 不靠加油或强塞份量凑数；重新分配，必要时保留临床待确认 |
| 做法可执行 | 每道菜的菜名、做法与原料逐一对应，菜名不能暗示另有一份已拌入菜中的原料；称重状态明确；实际需要的和面、浸泡、蒸煮等步骤不能隐去；复杂菜能识别，非默认天天做 | 删除不存在配料/重复公共份额，补必要步骤或换成更易执行的菜 |
| 医嘱与耐受边界 | 新食物不冒充已耐受；没有疗效或症状保证类措辞；用药及饮水不越权；出现症状/准备失败的调整路径明确 | 删除疗效承诺、无据禁食和越权处方，重做有关搭配 |
| 展示与隐私 | 正文、明细、摘要同版本；组号跳转、表格完整；个人资料在仓库外；用户不生图就不生图 | 修展示并重新核对，不让“明细为准”掩盖摘要错误 |

**示例默认检查线（产品设计默认值，用户或营养师可替换或关闭；不是营养学推荐量）——大型任选库（20组及以上、没有特殊限制时）**：蔬菜/菌菇至少12种，其中非淀粉蔬菜/菌菇至少10种；不能只在整库出现，重点餐次也须覆盖至少10种；水果至少5种；每个正餐至少80%的主体食材集合不同（剔除固定奶类、调味料和种籽，按食材身份而非份量差统计）；同一晚餐主体蔬菜不占超过三分之一的组。地域时令优先要求还须看主次占比，不能只有一两道点缀。这些是防模板拼接的产品设计检查线，**不是营养学推荐量、必须吃遍的品种数或医学限制**。较短菜单、明确限食、食欲/耐受或采购限制不套用同一数量线：执行者先记录具体依据及适用目标，不能生成后为已失败的方案降低标准。

数字通过仍需读一遍真实餐食：是否愿意吃、能否做、是否存在多种原料但天天同一种口感。让未参与施工的独立AI审阅者核对本表与实际菜单，尤其检查“数据可算但生活不可行”的情况；审阅者需拿原始事实，而非只看施工者的结论。保留原始发现与处理，不用“已审核”三个字替代证据。

以下逐项作为上述验收记录的细查依据：

- 个人资料未写入仓库；通用方法中没有个人病情、路径或固定个人剂量。
- 菜单只有一个份量真源，核算可复现；分餐移动对比无意外加减。
- 每种食物的实际份量均有蛋白质、碳水、脂肪克数和重量状态；能追到每100g来源，并汇总到餐次和全日，估算及代理值已标出。
- 医嘱、习惯、估算、未知分开；允许不等于必须，没有把未填项写成“无”。
- 食物选择先于数据补齐；类别内轮换有检查，重复有实际理由，没有为方便核算封闭食材范围或为多样化加大总量。
- 健康生活方式总则与个体治疗边界同时满足；暂时偏离一般原则时说明理由及复评条件，没有以普适目标覆盖医嘱。
- 营养与耐受/医嘱分开说明，没有疗效或症状保证类措辞，也没有伪造专家签署。
- 交付指出变化理由、文件、真实测试结果、临床待确认项及未确认项。
