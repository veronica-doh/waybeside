# 饮食方案：先设计，验收后交付

> **免责声明**：本技能及其全部产出物（菜单、核算报告、验收记录等）均不是医疗建议，不构成诊断或治疗，不替代医嘱；完整条款见仓库根目录的 [DISCLAIMER.md](../../../DISCLAIMER.md)。每份产出物必须引用该文件。

适用于本仓库的饮食方案任务。自然语言提出生成、重做、调整饮食方案时即使用，无需用户再次要求“检查一下”。技能负责执行流程，不代表临床会诊或自动获得医疗、对外发送权限。

## 必读与唯一依据

从本技能目录向上三级定位仓库根目录。每次开始，读取根目录的 [饮食基线流程](../../../docs/nutrition-baseline-workflow.md)，特别是总则、选材、全量核算和“交付验收”章节；该文件是设计和验收标准的唯一维护位置，不在这里复制数量阈值或医学目标；流程中的数量检查线只是“示例默认检查线”（产品设计默认值，可替换或关闭，不是营养学推荐量），不得当作医学目标。

读取本次用户资料的实际填写、上一版份量真源和最新反馈，区分事实、医嘱、偏好、估算和未知。用户已给过的答案不要重复询问；地域与季节按本次要求判断，不把任何个人案例的日期、偏好、克数或疾病固化为所有用户的默认值。医学建议和新食物数据需要时核对权威来源。

## 必经执行链

1. **确定需求与适用标准。** 明确组数/天数、是否任选、季节地域、餐次、做法、展示形式及本人边界。按流程选择适用检查线，限制导致例外时先记录依据，不在验收失败后降低目标。先选食物和菜式再补数据，不能被旧参考表限制。
2. **生成或修改唯一份量真源。** 在仓库外的本次私有输出目录保存 `menu.json`，原始健康资料也留在仓库外。结构按流程及核算脚本约定。包含全部食物、油奶配料、生熟重、每100g来源与估算限制；从真源生成逐食物P/C/F、餐次/全天合计、做法与正文。
3. **自动执行机械核算。** 不等用户提醒，从仓库根目录运行：

   ```sh
   python3 tools/verify_menu.py --menu "$MENU_PATH" --out "$CHECK_PATH"
   ```

   `MENU_PATH` 和 `CHECK_PATH` 由执行者绑定本次真实路径；输出不得覆盖输入。确认真实退出码、报告状态、菜单哈希。分餐迁移且应保全天份额时加 `--compare` 对照旧菜单，检查变化是否符合意图。不要把脚本PASS说成医学通过；`--expected`只检查每日合计，不能替代全文或每餐一致性。
4. **自动执行完整验收。** 按流程八项验收表核对当前版本，保存同目录 `验收记录.md`：每项写PASS/FAIL/未确认、证据和处理。统计各正餐实际主体食材集合、类别覆盖、出现频次与重复，检查地域季节是否落实、菜名/原料/做法是否一致、原习惯改变是否解释、每餐是否现实可吃。不能只运行脚本或复制标准当作验收完成。
5. **修正后复验。** 有可修正FAIL先自行修正并重跑受影响的核算、统计和展示检查；任何份量改变都重新核算整天，禁止手改合计。完成后确认正文、摘要、数据及验收记录属于同版，旧PASS不可沿用。不要让用户审批明显漏项或承担食材盘点、加总、查错工作。
6. **按流程独立审阅。** 实质性治疗期修订和需要独立审阅的方案，使用未参与写作的独立AI审阅者，提供原始事实、候选及验收表，保存原始发现、修正和复核。审阅者不可用施工者结论替代原始依据。若该能力不可用，如实保留未完成项，不伪造独立审阅或已验收。
7. **交付。** 给可用方案链接、关键变化和简短验收结果，完整记录附后；菜单与核算报告、验收记录的开头都写明“本文件不是医疗建议，见 DISCLAIMER.md”；用户不生图就不生图。营养核算与设计质量通过不代表临床适用性确认；已披露的临床未知可随候选交付，资料缺失若会改变安全决策则保留相应部分并只问真正必要的问题。

## 调整任务也不能跳过

- 换水果/蔬菜/品牌：补数据并重算实际份量，不按相同克数假设营养相同。
- 调整某一餐：重新核对整日与方案库相关多样性，不只修被指出的一格。
- 扩大组数：重新设计实际选择，不把少量整餐模板排列组合当作新增餐食。
- 纯排版：复用已验证真源，但检查摘要、份量、生熟重、公共栏、餐次及版本一致性；不无故重做医学研究。
- 验收未完成时只说明真实状态，不用“最终版”“全面通过”结束任务。用户可决定偏好与是否采用，不承担基础质量检查。

## 可用工具及维护验证

复用根目录 `tools/verify_menu.py`，不另造平行核算器。维护本技能或脚本时，可运行合成测试：

```sh
python3 -m unittest discover -s tools -p 'test_verify_menu.py'
```

技能为仓库级按需能力，没有后台任务，不更改全局配置，不上传用户资料。自动匹配由运行环境的技能发现机制提供；未被加载时可显式调用 nutrition-plan 技能，不得声称一个技能就是无法绕过的拦截器。`agents/openai.yaml` 是可选的、宿主专用的元数据，不影响本技能的使用。
